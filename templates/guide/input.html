So far every program has worked on numbers written into its code. input name; instead reads the next whole number from the program's input and stores it in a variable, so the same program can work on different numbers each time it runs.

{% call g.example(stdin="20 22") %} input a; input b; print a + b; {% endcall %}

The Input box under the example holds the numbers. Change them and press Run. In the playground they go in the Input drawer under the editor, and on the command line you can type them as the program asks, or pass them with --input "20 22".

  • Numbers are separated by spaces or new lines, and read in order.
  • Each input reads exactly one number. Extra numbers are simply left unread.
  • Reading when there's nothing left, or reading something that isn't a whole number, is a runtime error.
{% call g.example(stdin="7", expect="runtime") %} input a; input b; print a + b; {% endcall %}

Reading until a stop value

When you don't know in advance how many numbers are coming, agree on a sentinel: a special value that means "that's all". Read one number before the loop, and the next one at the end of each pass:

{% call g.example(stdin="5 10 15 0") %} total = 0; count = 0; input x; while x != 0 { total += x; count += 1; input x; } print count; print total; {% endcall %}

Another common pattern is to read how many numbers will follow first, and then loop that many times. You'll use it in the exercise.

{% call g.remember() %}
  • input n; reads the next whole number into n.
  • Numbers are separated by spaces or new lines, and running out is an error.
  • For an unknown amount, read until a sentinel such as 0.

    The input starts with a count n, followed by n numbers. Print the biggest of those numbers. For the input 4 7 2 9 3 the answer is 9.

    {% call g.hint() %}

    Read n, then read the first number into best. Loop n - 1 more times, reading a number each time and keeping it if it is bigger.
