The parser only checks shape. print total; is perfectly good grammar even if total is never defined, and so is calling a function with the wrong number of values. Semantic analysis checks meaning: does every name refer to something, and is everything used sensibly? It walks the syntax tree before any code is generated, so these mistakes are caught before anything runs.

{{ g.h2("Symbol tables and scope") }}

To know what a name refers to, the analyser keeps symbol tables: one for the global scope, and one for each function. A table maps each name to a Symbol recording what kind of name it is and every line that assigns or reads it.

{{ g.source("semantic.py", "Symbol") }} {% call g.stage("symbols") %} rate = 3; func cost(items) { total = items * rate; return total; } print cost(4); {% endcall %}

The tables follow MiniLang's scope rule, which is worth knowing exactly:

  • Inside a function, the parameters and every name the function assigns are locals. Each call gets fresh copies.
  • Any other name a function reads, like rate above, is looked up in the globals.
  • A function never sees the locals of the function that called it.
{{ g.h2("Two passes") }}

A function can be called before its definition appears, and two functions can call each other. So the analyser can't simply read from top to bottom. It makes two passes over the tree:

  1. Declarations: collect every function and its parameters, and every name that each scope assigns. After this pass, the tables are complete.
  2. Uses: walk the code in order, and resolve each name and call against the finished tables.
{{ g.source("semantic.py", "Analyzer.run", start="for stmt in program.statements:", end="fn.symbols[name].assigned.append(line)") }} {% call g.stage("symbols") %} print is_even(10); func is_even(n) { if n == 0 { return 1; } return is_odd(n - 1); } func is_odd(n) { if n == 0 { return 0; } return is_even(n - 1); } {% endcall %}

The call on line 1 comes before either definition, and the two functions call each other. Both are fine, because pass 1 has seen everything before pass 2 checks anything.

{{ g.h2("Definite assignment") }}

A name can exist and still have no value yet, depending on which way the program went. To spot this, pass 2 carries a set of the names that are definitely assigned at each point. Assignments add to the set. Where two paths join, only names assigned on both paths survive, so the meet is set intersection:

{{ g.source("semantic.py", "meet") }} {{ g.source("semantic.py", "Analyzer.stmt", start="if isinstance(node, If):", end="return assigned # the body may run zero times") }}

A loop body might run zero times, so whatever it assigns doesn't count after the loop. And None means "this path never reaches here" (it ended in return or break), so it drops out of the meet entirely. This kind of analysis is a must-analysis: a fact holds only if it holds on every path.

{% call g.stage("symbols") %} n = 4; if n > 2 { big = 1; } print big; {% endcall %}

big exists, because line 3 assigns it, so this isn't an error. But on the path where n > 2 is false it has no value yet, hence the warning.

{{ g.h2("Warnings") }}

Errors stop the program. Warnings let it run, but point at code that is probably a mistake:

WarningMeans
may be unassignedon some path, the name has no value yet where it's read
scope trapa function reads a global, then assigns the same name, which makes a separate local
unreachablecode after return, break or continue in the same block
unuseda variable, parameter or function that nothing reads or calls
dead storea value overwritten before anything reads it (found by liveness analysis, chapter 5)

The scope trap deserves its own look, because it's the one that surprises people most. Reading a local before the function assigns it falls back to the global, but the assignment then creates a local, so the global never changes:

{{ g.source("semantic.py", "Analyzer.read", start="if fn is not None and name in fn.symbols:", end='self.result.warn(line, "maybe-unassigned"') }} {% call g.stage("symbols") %} count = 0; func bump() { count = count + 1; return count; print 99; } spare = 5; print bump(); {% endcall %} {{ g.h2("Did you mean") }}

An undefined name is usually a typo. So when the analyser can't resolve a name, it compares it with every name it does know, using Python's difflib, and suggests the closest one if it's similar enough. It also knows the habits people bring from other languages, such as true:

Errors don't stop the walk either. Each one is recorded with self.error(…), and the analyser carries on, so a single run reports every undefined name and every bad call:

{% call g.stage("symbols", expect="semantic") %} count = 0; func average(a, b) { return (a + b) / 2; } print cout; print avrage(4, 8); print average(4); done = true; {% endcall %} {% call g.remember() %}
  • Semantic analysis checks meaning: every name resolves, every call fits.
  • Symbol tables hold globals, and each function's parameters and locals.
  • Two passes: declare everything first, then check uses, so order doesn't matter.
  • Definite assignment is a must-analysis: at a join, keep only what both paths assigned.
  • Errors are collected, not raised one at a time, and typos get suggestions.

    {% call g.stage("symbols", title="Your turn") %} total = 0; func add_all(n) { for i = 1; i <= n; i += 1 { total += i; } return total; } print add_all(5); {% endcall %} {% call g.answer() %}

Running it would still print 15, but the global total stays 0. Giving the function its own total = 0; before the loop makes the intent clear and removes the warning.
